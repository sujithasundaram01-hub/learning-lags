# Day 1: Mastering SQL Joins (INNER and LEFT JOIN)

### 📝 Topic Overview
In relational databases, data is often spread across multiple tables to reduce redundancy (Normalization). **SQL Joins** are used to combine rows from two or more tables based on a related column between them. Understanding Joins is critical for backend development and is a frequent topic in technical interviews.

---

### 💡 Key Learning Points
1.  **Relationship:** Joins work by matching a **Primary Key** in one table to a **Foreign Key** in another.
2.  **INNER JOIN:** Returns records that have matching values in both tables. If a row doesn't have a match, it is excluded.
3.  **LEFT (OUTER) JOIN:** Returns all records from the left table, and the matched records from the right table. If there is no match, the result is `NULL` on the right side.
4.  **The ON Clause:** This is where you specify the link between the tables (e.g., `TableA.id = TableB.user_id`).

---

### 💻 Practical Code Example

Imagine we have two tables: `Employees` and `Departments`.

**Employees Table:**
| emp_id | name | dept_id |
| :--- | :--- | :--- |
| 1 | Alice | 10 |
| 2 | Bob | 11 |
| 3 | Charlie | NULL |

**Departments Table:**
| dept_id | dept_name |
| :--- | :--- |
| 10 | Engineering |
| 11 | Marketing |
| 12 | Sales |

#### 1. INNER JOIN (Finding employees with assigned departments)
```sql
SELECT Employees.name, Departments.dept_name
FROM Employees
INNER JOIN Departments ON Employees.dept_id = Departments.dept_id;
```
**Result:** Alice (Engineering), Bob (Marketing). *Charlie is excluded.*

#### 2. LEFT JOIN (Finding all employees, even those without departments)
```sql
SELECT Employees.name, Departments.dept_name
FROM Employees
LEFT JOIN Departments ON Employees.dept_id = Departments.dept_id;
```
**Result:** Alice (Engineering), Bob (Marketing), Charlie (NULL).

# Day 1: Mastering SQL Joins (INNER vs. LEFT JOIN)

### Explanation
In relational databases, data is often spread across multiple tables to reduce redundancy (a process called normalization). **SQL Joins** are used to combine rows from two or more tables based on a related column between them. Understanding how to fetch data across tables is a fundamental skill for backend development and data analysis interviews.

### Key Learning Points
1.  **INNER JOIN**: Returns records that have matching values in both tables. If a row in one table doesn't have a corresponding match in the other, it is excluded from the result.
2.  **LEFT (OUTER) JOIN**: Returns all records from the left table, and the matched records from the right table. If there is no match, the result is `NULL` on the right side.
3.  **The `ON` Clause**: This is where you specify the "bridge" (usually a Primary Key from one table and a Foreign Key from another).
4.  **Performance Tip**: Always join on indexed columns (like IDs) to ensure queries run fast as your data grows.

### Practical Code Example
Imagine we have two tables: `Employees` and `Departments`.

**Employees Table:**
| EmpID | Name | DeptID |
| :--- | :--- | :--- |
| 1 | Alice | 101 |
| 2 | Bob | 102 |
| 3 | Charlie | NULL |

**Departments Table:**
| DeptID | DeptName |
| :--- | :--- |
| 101 | Engineering |
| 102 | Marketing |

#### 1. INNER JOIN (Get only employees assigned to departments)
```sql
SELECT Employees.Name, Departments.DeptName
FROM Employees
INNER JOIN Departments ON Employees.DeptID = Departments.DeptID;
```
*Result: Alice (Engineering), Bob (Marketing). Charlie is excluded.*

#### 2. LEFT JOIN (Get ALL employees, even those without a department)
```sql
SELECT Employees.Name, Departments.DeptName
FROM Employees
LEFT JOIN Departments ON Employees.DeptID = Departments.DeptID;
```
*Result: Alice (Engineering), Bob (Marketing), Charlie (NULL).*
